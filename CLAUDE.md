## The UI tools in this project

Three reusable UGUI tools, each a self-contained folder with its own `README.md`. **Read the relevant README before changing a tool.** They are independent — no tool references another.

| Folder | What it does | Namespace |
| --- | --- | --- |
| `DOTweenAnimationPlayer/` | Inspector-authored DOTween animations, played by name | `rmf_claude.DOTweenUI` |
| `FlipbookAnimation/` | Sprite-frame flipbooks on UGUI `Image`s | `rmf_claude.FlipbookAnimation` |
| `SelectableEvents/` | UnityEvents for Selectable pointer/selection callbacks | none — global |

`SelectableEvents` is hand-written by the project author. Do not restructure, namespace or "modernise" it without being asked.

Common to all three: runtime types are `public`, editor-only drawers and custom editors are `internal`, and the `.meta` files carry the script GUIDs — **a folder copied without them loses every component on existing prefabs.**

**Do not add an `.asmdef` to any of these folders.** DOTween's UI shortcuts (`DOAnchorPos`, `DOFade`, `DOColor`, `DOSizeDelta`, the TMP ones) are *generated by the DOTween Setup panel* into `Assets/Plugins`, which compiles into the predefined assembly `Assembly-CSharp-firstpass`. An asmdef cannot reference a predefined assembly, so adding one silently deletes every one of those shortcuts — no error, just methods that no longer exist. The `Editor/` subfolder name is the only mechanism used to separate editor code, and it needs no configuration.

## DOTweenAnimationPlayer

Requires **DOTween Pro**. After importing it, run `Tools → Demigiant → DOTween Utility Panel → Setup DOTween…`; this is not optional and not the same as importing DOTween, and skipping it produces errors pointing at *this* code rather than the real cause.

`UIAnimationPlayer` holds a list of named animations, each a list of steps, and plays them: `player.Play("Show")`. A step drives one property on one target — anchored position, scale, rotation, colour, alpha, size delta, offset min/max, material float/colour, `SetActive`, punch, shake, or a sound. Steps run in sequence or joined to the previous one, with per-step delay, duration, ease and endpoint mode (`Absolute` / `Baseline` / `Current`). It is deliberately generic and knows nothing about menus, HUDs or transitions — **do not add game-specific logic to it.**

Things that look wrong but are intentional:

- **Reversing is an authoring operation, not a playback mode.** `Mirror Animation` / `Duplicate as Mirrored` rewrite the data once, so a mirrored `Show` is a real, editable `Hide`. There is no runtime `PlayReverse`, and **there should not be** — a live reverse mode and an authored mirror are two answers to the same question, and having both was tried and cut.
- **Mirroring deliberately does not touch easing** — neither the `Ease` preset nor a custom curve. The house style is that things decelerate into place in *both* directions, so a mirrored `Hide` keeps the `Out` ease its `Show` was authored with. Ease inversion was built, then removed on request. Do not reintroduce it.
- **`PlayAnimation` / `StopAnimation` are not redundant wrappers around `Play` / `Stop`.** Unity's UnityEvent dropdown only lists methods returning void with at most one argument, which excludes `Play` (returns a `Sequence`) and `Stop` (an optional parameter reads as two overloads). A void `Play(string)` cannot be an overload — C# does not overload on return type.
- **Stepped playback ("Play At Custom FPS") is implemented on the ease, not on the clock.** It quantises the *time* handed to the underlying ease, so the tween still updates every frame but holds its value between boundaries. Every step shares one grid keyed off its absolute sequence position — per-tween grids read as jitter. Punch and shake are excluded because they drive their own oscillation.
- **`WithPrevious` steps are groups, not rows.** Anything reordering a step list must keep each group's members together and contiguous, or it silently re-parents which steps are joined to which.
- **`AnchoredPosition`, `SizeDelta`, `OffsetMin` and `OffsetMax` all write the same rect.** Unity stores one rect and derives every view from it, so animating two of them on one target makes them overwrite each other. Any new rect-driving step type must also be added to `CaptureBaseline`, or `To: Baseline` collapses the target to zero.
- **A step's `Delay` is applied in exactly one place: the insert position `BuildSequence` computes.** `BuildTween` must never call `SetDelay` — DOTween adds a tween's own delay *on top of* its sequence position, so doing both doubles every delay. This regressed once already.
- `UIAnimationAudio.Shared` is the one global in the folder. For a mixer, call `UIAnimationAudio.SetShared` once rather than adding another.

DOTween behaviours worth knowing, all silent when violated: `SetLink` is a no-op on a tween inside a Sequence (apply it to the outer `Sequence`); a tween must be configured fully *before* `Append`/`Join`, since `DoInsert` sets `creationLocked` and `From`/`SetEase`/`SetRelative` then do nothing; `.From(value)` defaults to `setImmediately: true` and writes during construction rather than at t=0; a stencil `Mask` defeats material instancing because `StencilMaterial.Add` caches a copy that never re-syncs (`RectMask2D` is fine, and `MaterialPropertyBlock` does not work with UGUI at all); `TextMeshProUGUI` ignores `Graphic.material`, so use `TMP_Text.fontMaterial` and never destroy it. `SetUpdate(true)` is required for UI that animates while `Time.timeScale == 0`.

## FlipbookAnimation

No dependencies — not even DOTween. It only writes `Image.sprite`, so DOTween can move, scale and fade the same object at the same time; that split is intentional.

`UISpriteFlipbook` cycles an `Image` through a list of sprites. `UIFlipbookSelectable` sits *beside* a `Selectable` and picks the clip for its interaction state (Disabled > Pressed > Selected > Highlighted > Normal, matching Unity's own priority), leaving `onClick`, navigation and transitions untouched. `UIFlipbookClipAsset` is an optional ScriptableObject for sharing one clip across many objects.

Per clip: frames, FPS, loop mode (`Once` / `Loop` / `PingPong`) and timing mode (`Constant FPS` / `Random Offset` / `Per Frame Durations`).

Things that look wrong but are intentional:

- **A clip that merely ran out is not the same as one that was `Stop()`ped, and `OnEnable` tells them apart via `stoppedExplicitly`.** `Stop()` sets it, completion does not, `Play()` clears it. Without this a `Once` clip plays exactly once per scene load, and a panel shown, hidden and shown again sits frozen on its last drawing.
- **Randomised frame timing is rolled per pass on the *player*, never on the clip.** One clip asset can drive hundreds of objects, and rolling on the clip would give them all identical timing — the exact thing randomising was meant to prevent. `RandomStartFrame` lives on the player for the same reason.
- **Ping-pong turns at `count - 2`**, not `count - 1`, so the end drawings are not held for a double beat. A 4-frame clip reads `ABCDCBABCDCB`.
- **`Selected` deliberately does not fall back to `Highlighted`.** A button keeps EventSystem selection after a click, so borrowing the hover look while the mouse is elsewhere reads as a stuck button. An empty `Selected` means "no focus look".
- **Do not set the Selectable's Transition to `Sprite Swap`** — it writes `Image.sprite` itself and fights the flipbook. `OnValidate` warns about it.
- **`LoopMode` replaced a serialized `bool Loop`, and Unity cannot convert between them.** `MigrateLoop()` reads the legacy bool once, using the older `defaultsFilled` flag to tell authored data from a zero-filled new element. Both hidden fields must stay for any project still holding pre-migration assets.
- Sprite thumbnails use `GUI.DrawTextureWithTexCoords` over `sprite.textureRect` rather than `AssetPreview`, which loads asynchronously and returns null on the first repaints.
- The frame sort is numeric-aware, so `frame_2` precedes `frame_10` and `frame_007` lands beside `frame_7`.

## SelectableEvents

The project author's own code. `SelectableEvents` exposes UnityEvents for hover, unhover, press, release, click, select, deselect and submit on anything deriving from `Selectable`.

It implements the same EventSystem handler interfaces as `UIFlipbookSelectable`, and **that is fine** — the EventSystem delivers each event to *every* handler on the object, so both receive it and the Selectable's own behaviour is unaffected. Note the asymmetry in its guards: `OnHover` and `OnUnhover` fire regardless of `IsInteractable()`; press, click and submit do not.

## Shared conventions in the Claude-authored tools

Both use the same patterns, and anything added to them should too.

**Inspector-authored data classes need a `FillUnsetDefaults()` called from the owner's `OnValidate`.** Unity does not run C# field initialisers for elements added with `+` on a serialized `List<T>` — a new element is zero-filled, so `= 12f` / `= true` silently do not apply. `FillUnsetDefaults` only writes fields still at their zero value, so authored data is never clobbered. Where `false` is both "never set" and "the user unticked it", a hidden `defaultsFilled` bool is what distinguishes them.

**Serialized enums are stored as integers, and those integers are the contract.** Every enum here assigns its values explicitly (`Scale = 12`) so reordering the lines is harmless. *Changing* a number, or reusing a retired one, repoints every asset authored against it with no error and no warning. This cost a day once: alphabetising `UIAnimationStepType` turned 16 authored `Scale` steps into `GraphicAlpha` steps and faded a menu to invisible. It reads like lost references or a corrupt prefab, so **if animations "disappear", check the enum's history before blaming the asset** — the fix is to remap the stored integers, never to reorder the enum back. Any new Inspector-authored enum should assign its numbers explicitly from the start.

**Edit-mode preview animates real scene objects, and three things make that safe.** Both tools have one; all three mechanisms are load-bearing. Capture before and restore after, *per property* — never a blanket `EditorJsonUtility` round-trip of the component, which also rewrites object references and blanks things like an `Image`'s sprite. Re-capture baselines before *every* preview, so relative endpoints do not drift on repeats. Clear callbacks, because an `On Complete` UnityEvent is wired to arbitrary game code that must not run outside play mode. Plus: only one preview at a time (that is what guarantees the captured state belongs to the object being restored), one `Undo` entry as a backstop, `EditorUtility.SetDirty` on each touched object, and an unwind on selection change, play-mode change and assembly reload.

**Right-click menus are scoped by target object, not by type name.** `SerializedProperty.type` and `propertyPath` report *unqualified* names, so a namespace does not disambiguate them and another project's `UIAnimation` or `Frames` list would match a string comparison — require your own component as `serializedObject.targetObject` instead. Also `.Copy()` the property handed to the callback, since menu items run after it goes out of scope, and register `contextualPropertyMenu` **once per folder**: every handler appends to the same menu.

**When copying Inspector data, use `JsonUtility`, not `EditorJsonUtility`.** Despite the names, the plain one preserves `UnityEngine.Object` references (`{"instanceID":-228892}`) and the Editor one destroys them (`{"instanceID":0}`), because it serializes the way an asset file does, where a reference is a file ID an in-memory scene object does not have. This was backwards once and dropped every target slot on paste.

**Two Unity API limits these tools work around.** `[Range]` clamps typed input as well as the slider, so it cannot express "the slider stops at 12 but you may type 24" — draw the slider and the field separately, and only adopt the slider when it actually moved. And `GetPropertyHeight` is not given the inspector width, so a drawer whose height depends on what fits per row cannot be laid out honestly; use a fixed number of rows and truncate.

**Testing enable-time logic requires reflection.** Edit mode does not deliver `Awake` / `OnEnable` / `OnDisable` to a component without `[ExecuteAlways]`, so a test that toggles `SetActive` exercises nothing and quietly passes. Invoke the callback directly instead.
